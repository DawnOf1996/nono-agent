两个边界

这套设计覆盖的是「同一次页面生命周期内的会话切换」。下面两种情况不在保证范围内。

刷新页面无法无缝续流

runs 是内存态，F5 后丢失。此时 openSession() 走非 live 分支，从事件日志重建 —— 拿到的是已落盘的快照，不是续上的实时流。

要真续流，得让前端改用 GET /session/{id}/events?follow=true&after_seq=N 订阅，服务端那条通道本来就是支持的。

真断开连接会截断那一轮

客户端断开时 chat.py 的 finally 会 cancel() 掉 drain 任务，生成器随之取消，而引擎没有把这种取消转成 abort()。

表现是流被截断而非标记 aborted —— 这正是「切换会话必须保持连接、不能关 SSE」的原因。
